# Rust Starter

Rust Starter is a production-ready Axum backend starter that now ships through
the `@akshay2642005/rust-starter` npm CLI. Version `0.1.0` generates a complete Axum
service with authentication, SeaORM + Postgres, OpenAPI docs, migrations, and
built-in observability.

## What you get

- `npx @akshay2642005/rust-starter@latest` project generation.
- Axum 0.8 web server with clean routing and middleware.
- Better Auth for email/password, sessions, and account management.
- SeaORM store with Postgres connectivity.
- Hot-reloaded configuration from file + environment.
- OpenAPI schemas with Scalar UI in development.
- Prometheus metrics, health probes, and structured tracing.
- Rate limiting, security headers, request IDs, and timeouts.

## Quick start

Create a new service with the published CLI:

```bash
npx @akshay2642005/rust-starter@latest my-api
cd my-api
cp config.example.yml config.yml
docker compose up -d
cargo xtask migrate up
cargo run
```

The generated server starts on `http://localhost:8080` by default.

## Requirements

- Node.js 18 or newer for the CLI.
- A Rust toolchain that supports edition 2024.
- PostgreSQL, or Docker + Docker Compose for the bundled local database.

## CLI usage

The v0.1.0 CLI accepts an optional project directory name:

```bash
npx @akshay2642005/rust-starter@latest my-api
```

If no name is provided, the CLI prompts for one:

```bash
npx @akshay2642005/rust-starter@latest
```

Project names are normalized to lowercase kebab case. The generator also
creates a fresh `auth.secret` value for the new project.

## Project layout

- `src/main.rs`: bootstraps configuration, telemetry, and the HTTP server.
- `src/app.rs`: wires the router, middleware, and server runtime.
- `src/handlers`: contains system, auth-adjacent, and todo HTTP handlers.
- `crates/configuration`: loads, validates, and hot-reloads config.
- `crates/seaorm`: provides database entities, store setup, and repository helpers.
- `crates/telemetry`: configures tracing, metrics, and optional OTLP export.
- `tooling/xtask`: runs migrations, checks, benches, and entity generation.

## Core endpoints

- `GET /health`, `GET /readyz`, `GET /status`: system probes.
- `GET /todos` and `POST /todos`: todo APIs (protected).
- Auth endpoints are mounted under your configured `auth.path_prefix`.
